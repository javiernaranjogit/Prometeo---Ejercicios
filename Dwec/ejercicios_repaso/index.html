U2 · JavaScript Básico (S3–S5)

U2·S3EJ 01

let vs const

Declara una constante PI con valor 3.1416 y una variable radio con valor 5. Calcula y muestra el área del círculo (PI * radio²). Después intenta reasignar radio a 10 y vuelve a calcular el área. Usa console.log.

SOLUCIÓN
const PI = 3.1416;
let radio = 5;
console.log("Área:", PI * radio ** 2);   // 78.54
radio = 10;
console.log("Área:", PI * radio ** 2);   // 314.16

Si declararas radio con const, la reasignación lanzaría TypeError: Assignment to constant variable.

U2·S3EJ 02

Coerción y comparación estricta

Crea una función iguales(a, b) que devuelva true solo si a y b son iguales en valor Y tipo. Pruébala con: "5" y 5, 0 y false, null y undefined, 3 y 3.

SOLUCIÓN
function iguales(a, b) {
  return a === b;  // estricta: valor + tipo
}
// false, false, false, true

Con == los tres primeros darían true por coerción. Por eso siempre ===.

U2·S4EJ 03

map, filter, reduce

Dado el array productos, devuelve un array con los nombres en mayúsculas de los productos cuyo precio sea menor o igual a 50, y muestra también el total sumado de TODOS los precios.

SOLUCIÓN
const baratos = productos
  .filter(p => p.precio <= 50)
  .map(p => p.nombre.toUpperCase());

const total = productos.reduce((acc, p) => acc + p.precio, 0);

console.log(baratos); // ["TECLADO", "RATÓN"]
console.log(total);   // 295

El patrón filter → map es muy común. reduce con acc inicial 0 acumula.

U2·S4EJ 04

Funciones flecha y this

Crea una función multiplicador(n) que devuelva otra función que, dado un valor x, devuelva x * n. Úsala para crear doble y triple.

SOLUCIÓN
const multiplicador = (n) => (x) => x * n;
// equivalente a:
// function multiplicador(n) { return function(x) { return x * n; } }

Esto se llama closure: la función interna recuerda el n de la externa.

U2·S3EJ 20

Destructuring + spread/rest

A partir del objeto usuario: 1) extrae nombre y email en variables sueltas, y agrupa el resto en ...resto. 2) Crea usuarioActualizado combinando usuario con { edad: 31, ciudad: "Madrid" } SIN mutar el original.

SOLUCIÓN
const { nombre, email, ...resto } = usuario;
console.log(nombre);   // "Ana"
console.log(email);    // "ana@x.com"
console.log(resto);    // { edad: 30, rol: "admin" }

const usuarioActualizado = { ...usuario, edad: 31, ciudad: "Madrid" };
console.log(usuarioActualizado);
console.log(usuario.edad);  // 30  ← original intacto

El spread {...a, b} es la forma idiomática en React de actualizar estado sin mutar. Las claves posteriores ganan.

U2·S5EJ 05

Contador con addEventListener

Tienes un botón y un span (los crearé yo cuando ejecutes). Escribe el código que, al hacer click en el botón #btn, incremente contador y lo muestre en #out. Usa textContent (seguro frente a XSS).

SOLUCIÓN
const btn = document.getElementById("btn");
const out = document.getElementById("out");
let contador = 0;
btn.addEventListener("click", () => {
  contador++;
  out.textContent = contador;
});

textContent es seguro: si pones HTML lo escapa. innerHTML lo interpretaría (XSS).

U3·S6EJ 06

Eliminar duplicados con Set

Dada una lista de emails con duplicados, devuelve un array con cada email solo una vez, en orden de aparición.

SOLUCIÓN
const unicos = [...new Set(emails)];
console.log(unicos);
// ["ana@x.com","luis@x.com","marta@x.com","pepe@x.com"]

Set garantiza unicidad y mantiene orden de inserción. El spread ... lo convierte a array.

U3·S6EJ 07

Map de usuarios por ID

Crea un Map donde la clave sea el id del usuario y el valor el objeto completo. Después busca el usuario con id 2.

SOLUCIÓN
const mapa = new Map(usuarios.map(u => [u.id, u]));
console.log(mapa.get(2));        // { id: 2, nombre: "Luis" }

A diferencia de un objeto literal, Map admite claves de cualquier tipo y mantiene el orden de inserción.

U3·S6EJ 08

JSON: guardar y leer un objeto

Convierte el objeto config a una cadena JSON, luego conviértelo de vuelta a objeto y muestra el valor de config2.tema.

SOLUCIÓN
const str = JSON.stringify(config);

U3·S7EJ 09

Validación de formulario

Crea una función validar(email, password) que devuelva { ok: true } si el email tiene formato válido y la contraseña tiene al menos 8 caracteres. Si no, { ok: false, error: "mensaje" }.

SOLUCIÓN
function validar(email, password) {
  const re = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  if (!re.test(email)) return { ok: false, error: "Email no válido" };
  if (password.length < 8) return { ok: false, error: "Contraseña muy corta" };
  return { ok: true };
}

Validar en cliente mejora UX pero el servidor SIEMPRE debe revalidar (cualquiera puede saltarse el JS).

U4 · DOM Avanzado y Async (S8–S9)

U4·S8EJ 10

Lista dinámica con createElement

Dado un array tareas, crea un <ul> con un <li> por cada tarea y añádelo a #contenedor (que ya existe). Usa textContent, NO innerHTML.

SOLUCIÓN
const ul = document.createElement("ul");
tareas.forEach(t => {
  const li = document.createElement("li");
  li.textContent = t;
  ul.appendChild(li);
});
contenedor.appendChild(ul);

Si una tarea contuviera <script>alert(1)</script>, textContent la mostraría como texto. innerHTML la ejecutaría.

U4·S9EJ 11

Promesa básica con setTimeout

Crea una función esperar(ms) que devuelva una promesa que se resuelva tras ms milisegundos con el texto "¡Listo!". Úsala con .then.

SOLUCIÓN
function esperar(ms) {
  return new Promise(resolve => {
    setTimeout(() => resolve("¡Listo!"), ms);
  });
}

Patrón clásico para convertir una API de callback (setTimeout) en una promesa.

U4·S9EJ 12

async/await + try/catch

Convierte este código con .then/.catch a una función async usando await y try/catch.

SOLUCIÓN
async function cargarAsync() {
  try {
    const r = await fetch("https://jsonplaceholder.typicode.com/todos/1");
    const data = await r.json();
    console.log(data.title);
  } catch (e) {
    console.log("Error:", e.message);
  }
}

El motor sigue usando promesas por debajo. await solo funciona dentro de funciones async.

U4·S9EJ 13

Promise.all en paralelo

Ejecuta 3 promesas esperar(300), esperar(500), esperar(200) en paralelo y muestra los resultados cuando todas terminen. Mide el tiempo total.

SOLUCIÓN
const resultados = await Promise.all([
  esperar(300), esperar(500), esperar(200)
]);
console.log(resultados);  // ["fin 300ms", "fin 500ms", "fin 200ms"]
// Tiempo ≈ 500ms (la más lenta), no 1000ms

En serie con await uno tras otro tardaría ~1000ms. En paralelo ~500ms (lo que tarde la más lenta).

U4·S8EJ 21

NodeList vs Array

En #items ya hay 4 <li>. Selecciónalos con querySelectorAll (devuelve NodeList). Convierte el NodeList a Array con Array.from() y usa map() para devolver un array con sus textos en mayúsculas.

SOLUCIÓN
const textos = Array.from(lis).map(li => li.textContent.toUpperCase());
console.log(textos);
// ["UNO", "DOS", "TRES", "CUATRO"]

// Alternativa con spread:
// const textos = [...lis].map(li => li.textContent.toUpperCase());

NodeList tiene forEach pero NO map/filter/reduce. HTMLCollection (de getElementsByTagName) ni siquiera tiene forEach.

U4·S8EJ 22

DocumentFragment para inserciones masivas

Inserta 500 <li> en #lista-frag. Hazlo con DocumentFragment (un único reflow al final) y mide el tiempo con performance.now().

SOLUCIÓN
const frag = document.createDocumentFragment();
for (let i = 1; i <= 500; i++) {
  const li = document.createElement("li");
  li.textContent = "Item " + i;
  frag.appendChild(li);   // ← en memoria, NO toca el DOM real
}
lista.appendChild(frag);  // ← UN solo reflow para los 500

Insertando uno a uno en el DOM real, el navegador recalcula layout 500 veces. Con fragment, solo una. Crítico en listas grandes.

U4·S9EJ 23

Debounce en un buscador

Implementa debounce(fn, ms): devuelve una función que solo ejecuta fn tras ms ms sin volver a llamarse. Aplícalo al input de #search para que solo "busque" cuando el usuario para de escribir 400ms.

SOLUCIÓN
function debounce(fn, ms) {
  let timer;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), ms);
  };
}

Patrón clásico en buscadores: evitas hacer 20 peticiones al servidor mientras el usuario teclea. Solo una cuando para.

U5 · APIs REST (S10–S11)

U5·S10EJ 14

GET con fetch + manejo de errores

Pide los datos de https://jsonplaceholder.typicode.com/users/1. Si la respuesta tiene res.ok === false lanza un error con el status. Si todo va bien, muestra el name.

SOLUCIÓN
async function getUsuario() {
  try {
    const res = await fetch("https://jsonplaceholder.typicode.com/users/1");
    if (!res.ok) throw new Error("HTTP " + res.status);
    const u = await res.json();
    console.log(u.name);
  } catch (e) {
    console.log("Error:", e.message);
  }
}

Recuerda: fetch NO rechaza con 404/500. Solo si falla la red. Hay que comprobar res.ok a mano.

U5·S10EJ 15

POST con fetch

Envía un nuevo post a https://jsonplaceholder.typicode.com/posts con los campos title y body. Recuerda method, headers con Content-Type y body con JSON.stringify.

SOLUCIÓN
async function crearPost() {
  const res = await fetch("https://jsonplaceholder.typicode.com/posts", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ title: "Repaso", body: "Hola DWEC" })
  });
  const data = await res.json();
  console.log(data);  // incluye el id asignado por el servidor
}

jsonplaceholder simula la creación pero no la persiste. Te devuelve el objeto con un id.

U5·S11EJ 16

apiService.js — patrón

Define un módulo apiService (objeto literal) con métodos getAll(), getById(id) y create(data) que centralicen la URL base. Úsalo para pedir el usuario 3.

SOLUCIÓN
const apiService = {
  getAll:    () => fetch(API).then(r => r.json()),
  getById:   (id) => fetch(`${API}/${id}`).then(r => r.json()),
  create:    (data) => fetch(API, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(data)
  }).then(r => r.json())
};

La ventaja: si cambia la URL base o necesitas añadir un token, lo tocas en UN solo sitio. Los componentes se quedan limpios.

U5·S10EJ 24

Fetch encadenado (dependiente)

Pide primero el usuario /users/1. Después, usando su id, pide sus posts en /posts?userId={id}. Muestra cuántos posts tiene y el título del primero.

SOLUCIÓN
async function postsDelUsuario() {
  const API = "https://jsonplaceholder.typicode.com";
  const u = await (await fetch(`${API}/users/1`)).json();
  const posts = await (await fetch(`${API}/posts?userId=${u.id}`)).json();
  console.log("Usuario:", u.name);
  console.log("Posts:", posts.length);          // 10
  console.log("Primer título:", posts[0].title);
}

Aquí los await tienen que ir en serie porque el segundo depende del primero. Si fueran independientes, Promise.all sería mejor.
